# Signed instance title disposition

The signed public adapter exposes POST `/api/v1/manga/{uuid}/lock`, POST `/api/v1/manga/{uuid}/unlock`, and DELETE `/api/v1/manga/{uuid}`. Every operation requires exact NIP-98 proof bytes and a closed JSON body containing the current positive `version` and mandatory captured native-account public UUID `expectedAccountId`. DELETE additionally requires the signed `removalMode`, either `request-review` or `approve-hide`; lock/unlock reject that extra field. The typed User UUID must resolve to the same freshly bound native write actor inside the final transaction. Neither a cookie nor a UUID grants authority.

Disposition commands reject duplicate JSON fields, including identical values and escaped field names that decode to the same key. The adapter parses the signed bytes directly into separate closed lock/removal command types; it never collapses fields through an intermediate JSON map. A body containing both review and approval effects is ambiguous and returns400 before any catalogue/report mutation. These commands have only scalar fields; arrays and nested account/effect objects remain invalid. This is an input-intent correctness boundary, not an additional authority grant or a change to removal policy.

Lock/unlock are retained-platform extensions. They require current instance moderator/staff status plus `manga.lock.update`, live source visibility, exact version, and the existing immutable pending-publication fence under the title row lock. A successful actual manga entity advances one version, exposes the actual lock state, and discloses instance-local metadata scope without rewriting source event identity. The shared native core retains the existing native unversioned transport while recording exact old/new audit versions.

Public DELETE with `removalMode='request-review'` is review-first for a current title owner with `manga.create`, including published and locked titles. It creates an operation-only private `manga_removal_request` report and audit with the reviewed title version and returns202 plus its real report UUID. The title version and visibility do not change, even if the same actor gains moderator removal authority after capturing that review-only intent. Duplicate requests at the same version return that same pending report. A changed target with an older pending review returns409. The normal per-user hourly report budget is checked before creation. Migration0101 disables the reserved reason in generic report creation/discovery; generic POST/report cannot bypass owner/version preflight.

A moderator with `manga.delete` can explicitly approve a current-version instance soft hide through DELETE with `removalMode='approve-hide'`, receiving actual204. This mode rechecks current moderator grants and never falls back to an owner review when they are missing. Pending title-removal reports are closed with attributable acceptance audit in the same transaction. Existing native report acceptance also requires `report.update`, `manga.delete`, live target visibility, and a matching captured target version before using the same native soft-hide core. Report acceptance and direct DELETE lock the title before its reports. A stale review can be rejected without requiring a currently visible target. Row/audit/version changes roll back together on a failed review transaction.

This operation does not permanently delete catalogue rows, chapters, stored image objects, or original protocol data. Public catalogue/reader predicates hide children through their locally hidden parent. Original deletion infrastructure currently supports chapter-kind1001 requests only; this title adapter sends no original deletion request and never manufactures a kind5 or approval. Responses state `sourceDeletionStatus='not-requested'`; actual original title identity is retained when present. All signed disposition successes/refusals carry private/no-store and Authorization variation, preserving existing Origin variation and503 privacy.

The dedicated title controller shares its exact signer/service/catalogue/account owner, canonical title read, busy state and durable unknown-outcome marker across metadata and disposition. Unknown network/5xx/malformed/privacy/provenance outcomes stay read-only without replay across reads/remount. Confirmed4xx and transport-proven unsent requests clear their marker. The UI separately confirms owner review (visible until approval) and immediate moderator hide. Unsaved title metadata blocks child/review actions; an explicit reload asks before discarding it. An accepted-pending original publication stays read-only.

Native cookie behavior is deliberately preserved: an unlocked nonpublished draft owner with `manga.create` can still immediately soft-hide their draft through the older native DELETE endpoint. Public DELETE always requires review for ordinary owners. Neither behavior is permanent deletion.
