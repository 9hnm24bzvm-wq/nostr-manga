# Explicit UUID-v2 publication and per-key canonical recovery

Anonymous device saves remain local UUID records. Only an explicitly initiated publication preview calls the versioned read-only mapper. It collects exact typed public UUIDs, including each saved chapter's manga, and uses actual verified original event IDs. A chapter enters a graph only when its original series event and preferred public parent agree with the saved manga's verified mapping. Hidden, local-only, wrong-parent and unresolved legacy rows remain local and are listed as excluded. No UUID/native/event ID is guessed or converted by shape.

The worker opens the existing device database without downgrading its schema or creating a missing database. It checks the exact durable device owner, scope, revision and migration fence. Full mapping fingerprints cover requested/canonical aliases, actual source event, publisher, kind, compatibility UUID and parent. The original canonical codec builds unchanged graph bytes. The original signer, admission, durable outbox, relay-revision CAS and HTTP acceptance rules remain authoritative; finite tests do not prove external acceptance.

Canonical protocol state now uses additive databases scoped by public API origin and selected signing public key. Returning to a key reopens only that key's canonical data; same-key reconnect also invalidates in-flight results through the signer generation. Before connecting a key, relay preferences use a separate settings-only database. The old global canonical database is never automatically imported, cleared, renamed or assigned to a key. An explicitly labelled local legacy backup export remains available. Adopting it requires choosing the intended key and explicitly reviewing a canonical import; broadcasting is a separate reviewed consent action.

Settings clear canonical rows, import/publication/recovery reviews, jobs and destinations on key-generation changes. Canonical read results and deletion selections carry their reviewed key and generation. Canonical backup export is selected-key scoped. Device baseline data and the device/account mode preference remain separate.

Library destinations must pass signed service identity verification and bounded origin/key/version-scoped advertised support for original public libraries before selection/preview/publication/retry/recovery. Advertised support is configured capability evidence, not account admission, health or acceptance. Publication still requires explicit public consent and the original protocol's own server response/proof. No external relay or real-key broadcast was performed.
