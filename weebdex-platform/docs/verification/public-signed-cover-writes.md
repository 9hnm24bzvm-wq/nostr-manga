# Signed public cover contract

This adapter uses existing NIP-98 admission, explicit native-account binding, current native catalogue grants, UUID aliases, cover publication/update/deletion audit, and durable image-object staging. No cookie grants public write authority. It creates no schema, compression or derivative variant. Native upload behavior keeps its existing derivative generation; the new original-only cover receiver reuses the same filename/MIME/magic/full-decode/byte/pixel/GIF validation and original storage leases while disabling every encoder.

- POST `/api/v1/cover/{mangaUuid}`: exact signed raw multipart, first plain `expectedVersion` field is the positive parent title version, second plain `expectedAccountId` is the captured native-account public UUID, then one `file` and optional `locale`, `volume`, `description`, `main` fields. Unknown/repeated fields fail. The parent, fresh binding/grants, visibility and immutable pending-command fence are rechecked before decoding and again before commit. Returns201 with actual cover UUID/version/parent and actual original digest/type/bytes/dimensions. It creates only an `original` media row. Covers are instance-local metadata until an independently authorized original title publication consumes the actual original bytes.
- PUT `/api/v1/cover/{coverUuid}`: signed JSON with exact positive cover `version`, required `expectedAccountId`, optional `locale`, `volume`, `description`, and retained `main` extension. File identity/dimensions cannot change in place. The native version, parent-first lock order, permissions and audit remain authoritative. Nullable volume maps to the native empty representation; unsupported nullable description is rejected rather than silently discarded.
- DELETE `/api/v1/cover/{coverUuid}`: signed JSON `{version, expectedAccountId}`. Existing policy requires actual instance staff/moderator status plus `cover.delete`; ordinary title ownership cannot bypass approval. This is an explicitly approved instance-local soft hide/media unlink, never original event deletion or automatic source approval. Stale cover versions fail409.
- GET `/api/v1/nostr/manga/{mangaUuid}/covers`: signed explicitly bound read, one repeatable-read snapshot per explicit page, at most100 actual visible cover resources with honest total/limit/offset. `limit` accepts0..100 (the private extension retains default100); `offset` accepts non-negative exact JSON/JavaScript integers. The signed editor sends its captured `expectedAccountId` in the URL, which is checked in that same transaction. Ordering remains created-at descending with native-ID ascending ties. No title-wide history cap or automatic whole-collection fetch is imposed. See [pagination contract](../signed-cover-editor-pagination.md). Drafts require their current owner with `manga.create` or staff with `manga.cover.edit`; hidden/source-withdrawn parents remain404. No native ID is exposed as a public resource ID.
- GET `/api/v1/nostr/covers/{coverUuid}/original`: the same signed read policy, existing bounded immutable original streaming, private/no-store, actual MIME/ETag and original bytes. No cookie fallback or derivative placeholder. Source-backed covers without an instance-local original media row remain unavailable through this local-original extension; their existing original protocol read route is separate.

Cover attributes carry `nostr.metadataScope='instance-local'`, actual source event when present, actual original descriptor when locally stored, actual main flag, and `originalEventRewritten:false`. Neither upload nor metadata edit claims original publication or public readability.

The owned HTTP fixture extends `public_manga_writes`' existing title lifecycle, avoiding duplicate static fixture accounts in a shared fixture database. It tests signed upload/tamper/replay/owner/version gates, exact PNG bytes and no derivatives, private listing/original reads, metadata-only CAS, moderator-only versioned removal, rollback of main-cover/alias/audit/object writes using an owned failing DB trigger, then uses the public cover as the real original title publication prerequisite. Runtime evidence is recorded separately after execution; this contract/source checkpoint alone is not a pass claim.

## Review corrections and browser contract

Every real main-cover demotion now advances that affected live cover's own version and updated timestamp and writes an actor-attributed `main-clear` audit entry. Rows already false, deleted rows, and the promoted target are excluded. Both native publication and metadata update use this shared parent-first helper. The owned HTTP seam reads A(main,v1), creates B(main), observes A(false,v2), rejects stale A(v1), promotes A(v2→v3), observes B(false,v2), and rejects stale B(v1). The rollback trigger also proves the demotion version and its audit roll back together.

All signed cover mutation and private extension responses carry `Cache-Control: private, no-store` and `Vary: Authorization`, including refusals emitted before handler admission. The outer boundary classifies the original external path, and existing Origin variation is preserved. Ordinary public GET cover resources retain their existing cache contract.

The dedicated public title form now mounts `PublicCoverEditor` for the exact acknowledged title/account. It serializes originals once, checks original digest/MIME/bytes and typed parent/version/provenance in receipts, refreshes actual grants/binding/scope immediately before dispatch, sends changed metadata only, and never calls native cookie cover/relation chains. Main changes require a fresh cover list before editing any other cover. The existing accepted-pending-projection title guard remains authoritative. Parent title commands and cover commands share UI busy/pending guards.

An unknown transport/server/malformed receipt outcome leaves a per-origin/service/catalogue/signer/native-account/title pending marker in session storage. Reads and remount do not replay or clear it. Confirmed4xx refusal and transport-proven unsent requests clear only their own marker. There is no fabricated success or automatic retry. Moderator deletion explicitly confirms the immediate instance-local hide.

Original previews require exact length, MIME, SHA-256, private/no-store, Authorization variation and nosniff, then use revocable local Blob URLs. The finite tests evaluate the actual controller, serializer and transport with real SHA-256 and explicit fake HTTP/signature primitives. They do not establish real browser decoding, IndexedDB, or live relay acceptance.

Every cover mutation requires captured signed native-account intent. The typed User UUID must resolve to the same bound native actor in its mutation transaction. Multipart intake checks before image decode and again afterward, retaining the early native actor ID for an explicit final equality check. A rebind to a different moderator with colliding valid grants returns409 for upload, metadata update and removal; those grants cannot replace the account the user reviewed. There is no shared auth helper/schema change on this lane.
