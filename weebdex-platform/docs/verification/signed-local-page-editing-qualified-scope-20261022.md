## What these controls establish, and what they do not

The mounted fixture compiles and mounts the current Svelte parent and child,
executes real runes/onMount/onDestroy and the actual controller/adapter, and
retains exact raw owner identity. Controls exercise explicit local provenance,
role/grant hints, fresh signer/service/account/chapter/version checks, mutually
exclusive metadata/page writes, confirmation, terms, cancellation, disposal,
double-click admission, exact accepted-session recovery, contradictory receipts,
and persistent uncertainty across remount in the same fixture runtime.

The native image-grid child is a stub. Mutex/context/navigation and the
signer/proof/HTTP service are bounded fixture seams. Therefore this is **not**
native-image-editor, original-image-byte upload, image decoding, upload progress,
full browser, real cryptography, SQL, or HTTP acceptance. The independent-new-
fixture late-disposal removal control is distinct from same-runtime remount
uncertainty; it does not prove cross-storage or cross-tab recovery.

The backend fixtures in `backend/tests/public_uploads.rs` are authored but not
executed here. They cover real existing native/signed core default/false copying
versus true empty staging, original bytes until atomic commit, cancel, bad
replace types, stale/revoked authority, exact editVersion, malicious metadata
not forging stored provenance, and protocol-backed source refusal. These remain
a separate Rust/HTTP/SQL qualification obligation, not a result of the finite
adapter's simulated responses.

Unknown begin without a previously witnessed accepted session ID deliberately
remains unresolved. Same account/chapter/version does not identify the original
attempt or replace mode. Read-only inspection does not clear that fence, replay
a mutation, infer mode from page count, or enable metadata/removal. A witnessed
accepted receipt can recover only the exact bound session and stored editVersion.

## Source and authority boundaries

`catalogue.rs` appends `_local_page_source_mutable` from the stored
`protocol_event_id IS NULL` fact after untrusted metadata merging.
`catalogue_dto.rs` projects only that boolean as `localPageSource: local|protocol`;
missing provenance fails closed. This is **source page-mutability eligibility**,
not edit permission. Current actor permission, captured version and owned session
are independently checked by the adapter and existing server core.

Signed begin-edit forwards the strictly parsed optional replace boolean to the
same native core. Omission/false retains its existing semantics; true requests
empty private staging, not live-page deletion. Receipt binding includes target,
version and replace mode. Commit/cancel retain the existing session owner,
atomic local-chapter path, commit/replacement fences and response binding.
Protocol-backed originals remain ineligible, distinct from local chapters.
Cookie-native mode and canonical frontend originals are not modified.

`normalize.ts` and `types.ts` are unchanged from f7. Normalization preserves the
resource in `public_api.resource`; `Resource.attributes` is already a typed
unknown-valued map. The new eligibility fact is read there, not inferred from
missing `attributes.nostr`. `PublicSession`'s edit version extension is in
`upload-client.ts`, not a rewrite of the canonical/native upload type.
