# Anonymous local UUID device writes

A caller explicitly opens `DeviceStore.open(scope,onChanged,onClosed,{idFormat:'public_uuid-v2'})`. A fresh empty library gets its durable anonymous owner marker and exact origin/catalogue UUID namespace. `serviceKey:null` is valid: no signer, account, network, original event mapping or publication is necessary to save a title, list, list member or chapter page progress. Already populated legacy libraries still require explicit reviewed ID migration. Legacy openers remain fenced from owner-marked v2 data.

All v2 mutations use one records/meta/sidecar transaction. They check the durable owner, exact scope, shared migration fence and optional revision CAS. New resource references must be UUIDs, local list IDs remain128bit, existing saved chapter parents cannot be rebound. Same-clock writes advance monotonically. List members require an existing local list. Unresolved legacy rows, immutable aliases and all recovery archives remain untouched by unrelated writes. Exact removals archive the prior row, preserve a durable tombstone, and cascade memberships. Full replacement stays a separately prepared, explicitly confirmed v2 restore; generic mutation cannot clear the database or use cursor-based writes.

Explicit service adoption may fill a null service key but cannot change a known service or namespace. Historical origin-only archives retain their original null-service provenance. Full v2 export and reviewed restore support anonymous namespace-only state and retain owner, aliases, issues, archives and tombstones. Restore checks immutable chapter parents, owner/scope and state fingerprint/CAS; old backups cannot resurrect deletion-fenced rows.
