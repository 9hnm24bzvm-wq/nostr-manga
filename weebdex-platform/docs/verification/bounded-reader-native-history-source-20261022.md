# Bounded reader native completion successor

This successor restores native account completion lookup for observed Continue scanning through the reviewed native-only completion route. It does not yet restore the retained one-click automatic native Continue interaction. It does not replace native account history with device history. Native completion means membership in the retained account chapter history, not a device `progress.completed` value. The current server/backend, browser, full type check and build are not qualified by this document.

## Admission and ownership

- Native requests use the configured API origin/base, the native cookie account actor and authority epoch, a mandatory expected-account header, `credentials: include` and rejected redirects. Public and ordinary selector/forum transport defaults are unchanged.
- Library selection starts its fence before storage or Session waits. After dynamic module loading, the selection is checked again before a mode-preference write transaction opens. The latest pending selection alone may clear its pending flag.
- Device and native history both capture library admission and its selection epoch. Native reads additionally recheck committed context, account revision, actor/authority epoch, endpoint, catalogue identity and action scope. Harmless Session data-generation refreshes alone do not impersonate an authority change.
- The network owner is shared across factory instances and retains its slot until actual settlement. A cancelled native request cannot publish late. A separate bounded device-IDB owner may operate after a mode change; no cross-owner dependence on an ignored cookie-network abort is introduced.
- Exactly ordered coverage of 1–50 selected server IDs, account/epoch and catalogue identity is validated from a plain minimal DTO. Missing, reordered, duplicate or invalid coverage never means unread. No device records, completion history or private note content is uploaded.
- Continue reserves worst-case selector plus history costs before starting either. A budget pause preserves the uninspected group or inspected anchor, never silently advances past it.
- A required reload is a persistent controller admission fence, including native identity/account/coverage conflicts. Start, Continue, verification, cancellation and context updates cannot clear it. The first accurate conflict message is retained; not every HTTP 409 is called a catalogue identity change.

## Honest user experience

The title explains device-local completion, native-cookie account history, unavailable public-account history and pending mode selection separately. Continue still offers an observed candidate, continued bounded scanning and explicit restart. A multi-request live scan cannot prove oldest unread or all read, and never automatically falls back to the newest chapter. The candidate replaces the retained single Continue Reading control with Continue scanning and a separate Open observed candidate action. That extra-action UX regression is distinct from the cross-request consistency limitation and is a blocker to replacement, not an accepted permanent limitation. The retained native control selected the oldest eligible group without an observed completed edition, or newest if all were read, then navigated for one edition or opened edition choice. A bounded one-click observed-candidate action could close the extra-click gap without proving global oldest unread; exact native-account global resolution would require a separately reviewed server contract. Main remains unchanged.
