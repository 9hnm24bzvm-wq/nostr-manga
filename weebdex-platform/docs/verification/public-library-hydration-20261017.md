# Public UUID device-library hydration

A strict read bridge now hydrates saved manga/chapter UUIDs through the actual public catalogue adapter, never through native `/api` IDs. Manga and chapter IDs batch at 100, followed updates use one explicit parent UUID per scope, and complete candidate sets are globally sorted/paged by the existing device-library owner. Empty sets make no request; non-visible rows stay absent. Duplicate, unrequested, wrong-parent, truncated, shifted, unstable or over-budget responses fail closed. Device membership/status/history is never inferred from public resources.

Current actual sortable fields are title/year/created/updated dates and chapter publication/chapter/volume. A local `readAt` view hydrates with publication order, then orders by its saved read time. Popularity and latest-upload sort values are not fabricated; they remain unavailable pending the backend's persisted exact sort-key extension. The global preview library write fence remains in this intermediate commit, pending validated mutable UUID-v2 storage/source mapping integration.
