# Anonymous UUID local-library integration

This follow-on replaces only the blanket public-catalogue local-library fence after the compatible owner/scope/CAS store (`1ae47a0`) landed. A fresh verified UUID catalogue opens an anonymous v2 device library, with no signup, Session, signer or publication. Existing populated native libraries still require reviewed migration; unresolved native rows remain in complete backups/recovery and are excluded from live UUID hydration. Stored account/device choice is preserved until the user explicitly changes it.

The existing title library controls, local lists/membership, followed updates, saved history, reviewed CSV import and full private backup export use this compatible store. CSV rows merge with exact scope/context/revision checks and retain owner, alias, archive, issue and deletion metadata. MyAnimeList lookup remains an explicitly native-ID response: each result must pass the existing typed namespace-bound public UUID resolver, then current visibility hydration, before a reviewed local merge. No UUID is inferred from a native ID's shape; ambiguous/missing/not-public results are excluded, conflicting imported reading states are rejected.

Manga sorting uses the backend's trusted `attributes.nostr.sortKeys` extension (`7434080`): exact decimal comparison for BIGINT/NUMERIC/year, supplied lowercase UTF-8 byte keys for titles, full fractional UTC dates and canonical UUID ascending ties. No display-title recomputation, rounded popularity or fabricated upload date is substituted. The public bridge still rejects unrequested, duplicate, wrong-parent, unstable, truncated and over-budget results. This supersedes the intermediate sort limitations recorded in `public-library-hydration-20261017.md`.

Reader progress continues offline only after this running tab verified the same saved catalogue scope. A failed network recheck retains the exact remembered scope; an observed namespace/service mismatch or migration fence revokes admission. The actual composed reader-history effect now uses that narrow admission seam. Live hydration and new title saves still need verification. A new/offline tab with no prior live verification cannot assert current-catalogue identity.

Native-cookie account-library mutation/import is not a UUID signed-command adapter. Public mode hides those unsupported choices, gives a stored account-mode selection a direct device-library recovery path, and rejects native catalogue/account transport before a request. Actual signed account read-only collections are not converted into invented reading status, timestamps or Session authority. Public library publication remains optional and owned by the separate reviewed publication path, never called by local saves.
