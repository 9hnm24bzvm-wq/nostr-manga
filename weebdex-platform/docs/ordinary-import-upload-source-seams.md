## File admission product correction

The composed `UploadChapter` passes `disabled={$mutex || !uploadSession}` to `UploadChapterPages`. The child uses the same context Mutex. `Mutex.exec` locks synchronously before running its callback, while the child `processFiles` and `replaceFile` formerly returned when inherited `disabled` was true. Thus each admitted input/drop callback rejected its own lock before decoding or uploading.

Script-only, exact-hash/anchor overlays now capture mutable staging before taking that mutex. Already-busy, externally disabled and immutable gestures remain blocked. The exact staging object and immutable target/account/lifetime owner are revalidated after asynchronous decoding, splitting, extraction, authority reads and digests, before local candidates or remote mutations, and before applying receipts. The actual batch receives a captured-session owner facade, so its authority-read, hash and final pre-POST checks cannot use only the longer-lived actor/target owner. Obsolete actor/session feedback is silent; honest current-session corruption and frozen-session feedback remain visible. Concurrent gestures remain rejected by the original mutex. No canonical frontend file or markup changes.

Live binding accessors reproduce inherited mutex-disabled behavior. Image decode and network/owner services are explicit stand-ins. Cases cover add/drop/replace, concurrent/busy/frozen/external denial, corrupt image/archive feedback, changed staging, account/lifetime invalidation during decoding, and genuine decode/batch errors.
