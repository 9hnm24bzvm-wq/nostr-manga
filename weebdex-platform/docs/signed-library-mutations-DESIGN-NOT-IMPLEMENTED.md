# Approved next design, NOT implemented

This design was approved immediately before the environment reset. No mutation code had been edited. Do not claim POST read/status implemented based on this document.

Standard MangaDex logical fields stay exact: chapterIdsRead/chapterIdsUnread, or required nullable status. Add explicit versioned nostr:{version:1,commit:{event,expected_head,objects}} using original library_wire bounded commit envelope. expected_head is REQUIRED, null only for genuinely absent head; never Any. New signed kind11999 event belongs to exact admitted proof principal. Exact original platform URL/method/body and selected service are signed; no URL rewriting/server signing/native account store.

The new root and only changed chunk objects are supplied. Preserve bucket counts and every unrelated family/bucket descriptor exactly by hash/size/count. Decode only affected old/new buckets using original Chunk summary/bucket validation. Every non-requested record stays byte/record-equivalent. Requested chapter completion changes preserve partial page state. Unread record removal only when no partial page would be erased. Status null removes only that series-status record. Original updated_at semantics remain signed client metadata, without an invented equality-to-event-time rule.

Bounds apply to changed bytes/records/request, independent of total library size: proposed16MiB/65536 changed record visits, existing64 objects/6MiB decoded/8MiB wire maximum plus existing platform default1MiB request limit, no auto-expansion. Root descriptor work O(chunks); no total-record scan/20k total graph cap. Rebucket via explicit existing original publication. Actual original indexed exact-ID/series/visibility lookup validates requested IDs. Genuine30k/500k graph fixtures should assert unchanged chunks were not read and affected lookup/record budgets, not claim a performance benchmark.

Use original admission receipt/processing, staging, grants, CAS commit, retention and outbox. An opaque header preflight may verify original signature/scope/service/admission before receipt allocation, but grants no authority until final exact-body verification and one replay consume. Selected-service/account-version guard must be inside original author commit transaction. Cancellation keeps owned mutation/storage leases until cleanup. Failed intent/stale CAS changes no public head/holds; late-CAS private staging follows existing reclamation. updateHistory=true remains explicit unsupported, since no actual readDate exists. Browser publication stays explicit; no automatic local-state sync.
