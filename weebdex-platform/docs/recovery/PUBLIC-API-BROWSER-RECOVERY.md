# Reconstructed browser acceptance runner

`scripts/public-api-browser-acceptance.mjs` is source-only recovery code and has not executed a real browser successfully. It uses the retained reviewed Playwright runtime loader, `chromiumSandbox:true`, a fresh browser context, blocked service workers, a deny-only external proxy and exact same-origin routes. It never uses the user's preview port60123 or an existing profile. It records actual requests/responses, uncaught page errors, console errors, screenshots and a cleanup receipt; it does not fake API responses.

Inputs are fresh owned absolute paths in `WEEBDEX_PUBLIC_API_FIXTURE_MANIFEST`, `WEEBDEX_PUBLIC_API_BUILD_RECEIPT`, and `WEEBDEX_PUBLIC_API_BROWSER_OUTPUT`, plus the expected40-hex `WEEBDEX_PUBLIC_API_FIXTURE_SOURCE`. The fixture shape matches the HTTP runner and additionally requires `no_forum_ids:{manga,chapter,group}`. Those are real public resources with no native forum context; their chapter still needs an actual image. The main chapter must have actual optimized media for this browser acceptance. The gate-on build receipt's SPA hash must match the actual served index bytes.

Thirteen intended browser stages cover home, search/author filter, UUID title/feed/cover, enabled Start Reading from actual public chapter availability, cover gallery, at-home original and advertised data-saver image decoding, author/group, scoped legacy link, visible missing-resource error, missing-context title/group and reader resilience, and the honest open Popular placeholder. Requests to native catalogue routes are aborted and fail acceptance. Actual image dimensions must be nonzero in the browser. Native forum records remain native inside their explicit companion extension; no fake thread UUID is allowed.

The Popular stage documents an open backlog, not completed popularity analytics. Mutation compatibility, library migration, device backup/export/import and all other API families are not accepted by this runner. The missing-forum reader stage explicitly sets only fresh-context reader preference keys from the pinned original source; it requires the localized unavailable message instead of silently swallowing a missing control.

No browser execution is authorized by this source file. The previous CUA inventory request was denied after the executor reset; do not retry that denied route without the required authorization. A restored supported browser/runtime and owned backend fixture are prerequisites, and the runner must be used only within approved acceptance scope. Fixture and browser must share a supported process network namespace when tool calls are isolated.
