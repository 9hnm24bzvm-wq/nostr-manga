## R3-PROTO-01 — P2: alternate platform backend bypasses terminal ownership

Evidence:

- `backend/src/protocol/publication.rs:162–172` opens the original backend when `OperatorRuntimeConfig.backend` is supplied. This is a distinct alternative to `native_node`.
- `publication.rs:283–287` launches that backend with raw `tokio::spawn(backend.clone().run())`. It provides no original `OWNED_OPERATIONS` context or independent process-terminal owner.
- `backend/src/config.rs:454–458,517–521,542–544` permits and validates this alternative outside production. It is rejected in production when the supervised original listener is absent; that restriction does not remove the supported nonproduction path.
- Original `../manga-protocol-lab/server/src/backend.rs:242,308–314` selects ownership only when `owned_context_active()` is true. For the platform's direct worker it is false, so the command remains inline and `OwnedCommand.embedded` is false. `backend.rs:40–43,106–117` then preserves ordinary standalone child-wait/drop behavior instead of process-group cleanup and sticky failure.
- `backend/src/main.rs:61–75,140–145,173–177` holds the direct worker handles, but shutdown aborts and observes only each Rust task before closing the shared pool. When `native_node` is absent, there is no native listener or original operation drain to supply the missing observation.

Concrete scenario: run a supported nonproduction original-backed platform using `protocol_publication.backend` and no `native_node`. A genuine timeout/flock/strfry projection command is in progress when SIGTERM starts shutdown. With no admitted request remaining, the platform request drain succeeds. Aborting the direct projection worker drops its inline subprocess wait; joining that Rust task does not terminate or observe its process group. The projection process can remain alive, retain its command lock and write the volume until its separate GNU timeout/kill-after boundary, despite the platform reporting a successful stop. The external timeout bounds survival but is not a terminal observation by the platform.

Impact and scope: inaccurate successful shutdown and projection-volume ownership release in the retained nonproduction configuration. This report does **not** claim that the supplied production `native_node` configuration uses this unowned branch, or that the now-patched original embedded command has the same defect.

Owner: platform catalogue/protocol runtime integration. Required source acceptance: either reject/retire the unsupported platform-owned backend-without-listener alternative before it opens a backend or spawns workers, or give that alternative the same actual subprocess/descendant terminal ownership and truthful drain/failure semantics. Preserve the original standalone node's deliberately unchanged behavior. Aborting only the Rust worker, adding kill-on-drop only for the leader, or relying on GNU timeout alone is insufficient.

Required later acceptance: if the branch is retained, hold a real original projection command after spawn, initiate platform shutdown and prove that success requires actual process-group termination with no later projection write. A missed deadline must report uncertainty. If the branch is rejected, verify both configuration validation and direct runtime configuration reject it before projection ownership/work starts, while the supervised native-listener configuration still opens normally.
